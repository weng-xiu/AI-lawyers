# AI 律师话务系统功能规划与完善方案

> 依据 `d:\project_job\AI-lawyers\img\` 目录下 10 张原型图片，对现有系统进行全面规划与差距分析，制定功能完善方案。

---

## 1. 项目背景与目标

### 1.1 背景
本系统为面向公共法律服务的 AI 律师话务与在线客服平台，原型已明确规划了统一工作台、咨询服务、客户服务、业务管理、质量管理、支撑系统六大类功能。当前仓库已完成 P0/P1/P2 三批次开发，但仍有大量原型所示功能尚未落地。

### 1.2 目标
- 系统梳理原型中的主功能模块与子功能组件。
- 对比现有代码（前后端）与原型差异。
- 制定可执行的功能完善方案与数据/接口补充建议。
- 明确实施优先级，指导后续迭代。

## 2. 原型主功能模块梳理

原型左侧菜单结构如下：

```

  ├─ IVR 服务管理
  ├─ 话务功能面板

  ├─ 图文对话服务
  ├─ 视频咨询服务
  └─ 通话录音
客户服务
  ├─ 客户回访中心
  ├─ 未接来电记录
  ├─ 回访任务管理
  └─ 留言服务
业务管理
  ├─ 台账管理
  ├─ 有偿法律服务管理
  ├─ 高频置底管理
  ├─ 工单管理
  └─ 签署记录管理
质量管理
  ├─ 智能风险预警管理

支撑系统
  ├─ 知识库
  ├─ 人脸识别
  ├─ 统计报表
```

### 4.2 已完善但可强化的模块

#### 4.2.1 统一工作台
原型要求：
- 顶部统计卡：今日通话、今日服务时长、服务满意度、在线时长。
- 我的待办：回访任务即将到期、工单待处理、预约服务单待确认、质检反馈待查看、新公告待阅读。
- 右侧：2026 年 7 月日历、快速入口（语音咨询、图文服务、台账登记、工单查询）。
- 最近通话记录表格：来电号码、咨询类型、坐席、时长、满意度。
- 公告栏。

现状：`workbench/index.vue` 已存在，但内容需与原型逐项对齐，尤其是日历、快速入口、满意度、公告。

#### 4.2.2 咨询管理中心
原型要求：多渠道咨询统一入口，支持语音、图文、视频、IVR 等渠道的汇聚、分类、分派、跟踪。

现状：`consultation/index.vue` 已实现基础列表与表单，但缺少视频渠道、留言渠道、智能分派。

#### 4.2.3 来电智能分析及管控
原型要求：独立的分析管控页面，含来电趋势、热点问题、坐席接通率、异常通话预警等。

现状：仅在 `callRecord.vue` 中通过弹窗提供基础统计（总来电、今日、本周、本月、分类饼图、日期折线），未形成独立模块。

## 5. 功能完善方案

### 5.1 首页 / 统一工作台

#### 5.1.1 完善目标
将工作台打造为坐席个人门户，聚合待办、数据、快捷操作与通知。

#### 5.1.2 子功能组件
1. **顶部统计卡**
   - 今日通话量（按坐席/全局）
   - 今日服务时长
   - 服务满意度（五星平均分）
   - 在线时长
2. **我的待办**
   - 回访任务即将到期
   - 工单待处理
   - 预约服务单待确认
   - 质检反馈待查看
   - 新公告待阅读
3. **日历组件**
   - 展示当月排班/预约/任务
   - 点击日期查看当日事件
4. **快速入口**
   - 语音咨询、图文服务、台账登记、工单查询
5. **最近通话记录**
   - 来电号码、咨询类型、坐席、时长、满意度
6. **公告栏**
   - 最新公告列表与详情

#### 5.1.3 接口补充
- `GET /lawyers/workbench/statistics`：今日通话、时长、满意度、在线时长。
- `GET /lawyers/workbench/todos`：各类待办数量与列表。
- `GET /lawyers/workbench/recentCalls`：最近 N 条通话。
- `GET /lawyers/notice/latest`：最新公告。

### 5.2 咨询服务

#### 5.2.1 图文对话服务（高优先级）

**现状**：仅有后端 `AiChatSessionController`、`AiChatSession`、`AiChatMessage`，无表结构脚本、无前端页面、无菜单。

**完善内容**：
1. 数据库建表
   - `ai_chat_session`：会话 ID、客户 ID、渠道（微信/网页/APP）、坐席 ID、状态（进行中/已结束）、创建时间、结束时间。
   - `ai_chat_message`：消息 ID、会话 ID、发送方类型（客户/坐席/系统）、消息类型（文本/图片/文件/语音）、内容、发送时间、已读状态。
2. 前端页面 `chat/im.vue`
   - 左侧会话列表（未读数、等待时间、来源渠道）
   - 中间消息气泡区（文本、图片、文件）
   - 右侧客户资料、历史会话、客户标签
   - 底部输入框（文本、表情、图片、文件、快捷回复）
   - 顶部转接、结束服务、邀评按钮
3. WebSocket 实时消息推送
4. 与 `ai_caller_profile`、`ai_legal_knowledge` 打通，实现客户画像与知识推荐。

**接口补充**：
- `GET /lawyers/chatSession/list`：会话列表
- `GET /lawyers/chatSession/{id}`：会话详情
- `GET /lawyers/chatMessage/list/{sessionId}`：消息列表
- `POST /lawyers/chatMessage/send`：坐席发送消息
- `POST /lawyers/chatSession/transfer`：转接会话
- `POST /lawyers/chatSession/close`：结束会话
- `WebSocket /ws/chat/{sessionId}`：实时消息

#### 5.2.2 视频咨询服务（高优先级）

**现状**：完全缺失。

**完善内容**：
1. 数据库建表
   - `ai_video_consult`：视频咨询记录 ID、客户 ID、坐席 ID、房间号、开始/结束时间、时长、状态、满意度、录像地址。
   - `ai_video_consult_log`：事件日志（加入、离开、共享、异常）。
2. 前端页面 `chat/video.vue`
   - 本地/远端视频窗口
   - 通话控制（接听、挂断、静音、摄像头切换、屏幕共享）
   - 侧边客户资料与身份核验结果
   - 咨询记录填写区

**接口补充**：
- `POST /lawyers/videoConsult/createRoom`：创建房间

- `GET /lawyers/videoConsult/list`：视频咨询列表

#### 5.2.3 来电智能分析及管控（中优先级）

## 8. 实施优先级与计划

### 8.1 优先级划分

| 优先级 | 模块 | 理由 |

| P0 | 统一工作台、话务功能面板、来电弹屏、未接来电、咨询管理中心、台账管理 | 核心业务已部分实现，需补齐与原型差异 |

## 10. 结论

现有系统已覆盖原型约 50% 的核心功能（话务、回访、台账、咨询、IVR、知识库），但原型中重点展示的**图文对话服务、视频咨询服务、有偿法律服务、签署记录、智能风险预警**等模块尚未落地。建议按 P0/P1/P2 优先级分阶段实施，优先补齐图文/视频对话与业务管理模块，再逐步完善质量管理、支撑系统与统计分析，确保最终系统与原型设计一致并满足业务闭环要求。
